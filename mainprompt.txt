3X-UI INTEGRATION MODULE  (packages/3xui/src/)
═══════════════════════════════════════════════════

3x-ui uses cookie-based session authentication.
The module MUST handle this correctly:

class ThreeXUIClient {
  private baseUrl: string;        // e.g. https://panel.example.com:2053
  private sessionCookie: string | null = null;
  private cookieTTL: number;      // store expiry time

  // Login → POST /login  { username, password }
  // Response sets a session cookie. Store it in Redis with TTL
  // matching the panel's session duration (default ~24h).
  // Key pattern: "3xui:session:{panelId}"
  async login(): Promise<void>

  // Auto-refresh: before every request, check if cookie is expired
  // (within 5-minute buffer). Re-login if needed.
  private async ensureSession(): Promise<void>

  // ─── Inbounds ───────────────────────────────────
  // GET  /panel/api/inbounds/list
  async getInbounds(): Promise<Inbound[]>

  // GET  /panel/api/inbounds/{id}
  async getInbound(id: number): Promise<Inbound>

  // ─── Clients ────────────────────────────────────
  // POST /panel/api/inbounds/addClient
  // Body: { id: inboundId, settings: JSON.stringify({ clients: [ClientObject] }) }
  // ClientObject: { id: uuidv4(), email, totalGB: bytes, expiryTime: ms, enable: true, tgId?, subId? }
  async addClient(inboundId: number, client: CreateClientDto): Promise<void>

  // POST /panel/api/inbounds/updateClient/{uuid}
  // Body: same shape as addClient but with existing uuid
  async updateClient(inboundId: number, uuid: string, data: UpdateClientDto): Promise<void>

  // POST /panel/api/inbounds/{inboundId}/delClient/{uuid}
  async deleteClient(inboundId: number, uuid: string): Promise<void>

  // GET  /panel/api/inbounds/getClientTraffics/{email}
  async getClientTraffic(email: string): Promise<ClientTraffic>

  // GET  /panel/api/inbounds/getClientTrafficsById/{id}
  async getClientTrafficById(id: number): Promise<ClientTraffic>

  // POST /panel/api/inbounds/resetClientTraffic/{email}
  async resetClientTraffic(email: string): Promise<void>

  // GET  /panel/api/inbounds/getClientIps/{email}
  async getClientIps(email: string): Promise<string[]>

  // POST /panel/api/inbounds/clearClientIps/{email}
  async clearClientIps(email: string): Promise<void>

  // ─── Online status ───────────────────────────────
  // POST /panel/api/inbounds/onlines
  async getOnlineClients(): Promise<string[]>   // returns list of emails

  // ─── Subscription URL ───────────────────────────
  // 3x-ui subscription URL format:
  // {panelBaseUrl}/sub/{clientSubId}
  // clientSubId is the `subId` field set during addClient (generate as nanoid(16))
  getSubLink(subId: string): string
}

IMPORTANT 3x-ui integration rules:
- Generate client email as: {productCode}-{userId}-{nanoid(8)}
  (must be unique per inbound, URL-safe, max 32 chars)
- Generate subId as nanoid(16) — store in our DB as Subscription.subLink
- totalGB is in BYTES: multiply GB value × 1_073_741_824
- expiryTime is Unix timestamp in MILLISECONDS: Date.now() + days×86400000
- If expiryTime = 0, the client never expires
- Store the 3x-ui panel password encrypted in DB using AES-256-GCM
  with key from env ENCRYPTION_KEY (32-byte hex string)
- Support multi-panel: each Product references a panelId;
  route all 3x-ui calls through the correct client instance
- Pool panel client instances in a Map<panelId, ThreeXUIClient>
- On panel connection error, mark panel as OFFLINE in DB + notify admins via bot

SECURITY REQUIREMENTS (ALL ARE MANDATORY)
═══════════════════════════════════════════════════

### Input Validation & SQL Injection
- Every API endpoint has a Zod schema; validation happens in a
  Fastify preHandler BEFORE any business logic runs
- Prisma ORM exclusively — zero raw SQL with user input
- Parameterize the rare raw queries that ARE needed
- All IDs exposed to clients are UUID v4 — never sequential integers
- Strip and reject unexpected fields (Zod .strict() on request bodies)

### XSS Prevention
- All user-generated content stored as plain text, never HTML
- Bot messages: use grammy's built-in parse_mode='MarkdownV2' safely;
  escape all user-supplied strings with a dedicated escapeMarkdown()
  utility before interpolating into messages
- Web panel: Next.js escapes by default; never use dangerouslySetInnerHTML
- Mini App: same — React escapes by default; DOMPurify on any raw HTML
- CSP header (set in Nginx AND in Next.js middleware):
  default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob: https:; connect-src 'self' https://api.telegram.org;
  frame-ancestors 'none';

### CSRF Prevention
- Web panel uses NextAuth sessions (HttpOnly, Secure, SameSite=Strict)
- All state-changing web panel API routes validate the CSRF token from
  NextAuth's built-in CSRF protection
- Fastify backend exposes API for bot + Mini App only — no cookie auth there;
  uses Bearer JWT exclusively for those clients
- Mini App: every request includes the raw initData string in header
  X-Telegram-Init-Data; server validates HMAC-SHA256 signature:
    const secret = crypto.createHmac('sha256', 'WebAppData')
                         .update(BOT_TOKEN).digest();
    const checkString = Object.entries(parsedInitData)
      .filter(([k]) => k !== 'hash')
      .sort(([a], [b]) => a.localeCompare(b))
      .map(([k, v]) => `${k}=${v}`)
      .join('\n');
    const hash = crypto.createHmac('sha256', secret)
                       .update(checkString).digest('hex');
    if (hash !== parsedInitData.hash) throw new UnauthorizedError();
  Reject initData older than 600 seconds (check auth_date field)

### Authentication & Authorization
- RBAC roles: SUPER_ADMIN | ADMIN | SUPPORT | USER
- Bot: check role on every admin command handler
- Web panel: Next.js middleware checks NextAuth session + role
- Fastify: JWT middleware extracts userId + role; each route declares
  required minimum role via a route-level preHandler
- JWT (RS256): access token TTL = 15 min, refresh token TTL = 30 days
- Refresh token rotation: on use, old token invalidated, new pair issued
  Family tracking: store all tokens of a family in Redis; reuse of
  revoked token → revoke ENTIRE family (token theft detection)
- Login rate limit: 5 attempts / 15 min / IP (Redis sliding window)
  On 5th failure: CAPTCHA challenge OR lockout for 15 min
- Admin login from web panel: require TOTP (2FA) if enabled in settings

### API Security (Fastify)
- @fastify/helmet: sets X-Content-Type-Options, X-Frame-Options,
  X-XSS-Protection, Referrer-Policy, Permissions-Policy
- @fastify/rate-limit: 200 req/15min global per IP; auth routes 5/15min;
  payment routes 10/hour per userId
- @fastify/multipart: limit file uploads to 5MB, accept only JPEG/PNG/WebP
  Validate file magic bytes (not just extension/mimetype header)
- Request body size: 100KB for JSON, 5MB for multipart
- Telegram bot webhook: validate X-Telegram-Bot-Api-Secret-Token header
  Set it in setWebhook call as secretToken = crypto.randomBytes(32).toString('hex')
  Store in env. Reject any webhook request without valid header.
- All 3x-ui panel passwords: AES-256-GCM encrypted at rest
- Env validation at startup: Zod schema checks all required env vars exist
  and are valid format; crash with descriptive error if invalid

### Audit Logging
- Every admin action creates an AdminLog record:
  { adminId, action: enum, targetType, targetId, metadata: JSON, ip, userAgent, ts }
- Admin actions include: USER_BLOCK, USER_BALANCE_CHANGE, RECEIPT_APPROVE,
  RECEIPT_REJECT, SUBSCRIPTION_SUSPEND, PRODUCT_CREATE, PRODUCT_EDIT,
  PANEL_ADD, BROADCAST_SEND, SETTINGS_CHANGE, ADMIN_ADD, ADMIN_REMOVE
- Audit logs are append-only (never update/delete through app code)
- Viewable from web admin panel with filter by action, admin, date range

BACKGROUND JOBS  (BullMQ — apps/server/src/jobs/)
═══════════════════════════════════════════════════

expiry-notifier (every hour):
  Query subscriptions expiring in exactly 3 days, 1 day, 6 hours.
  For each: fetch live traffic from 3x-ui, send personalized bot message:
  "⏰ سرویس شما {{productName}} تا {{timeLeft}} دیگر منقضی می‌شود.
   📊 ترافیک باقی‌مانده: {{remaining}} گیگابایت
   [🔄 تمدید سرویس]"

traffic-notifier (every 2 hours):
  Query active subscriptions.
  Fetch traffic for each in batches (concurrent limit: 5 per panel).
  Send warning at 80% and 95% usage (track sent warnings in Redis to avoid repeats):
  "⚠️ {{percent}}% از ترافیک سرویس {{productName}} مصرف شده است."

panel-health-check (every 3 minutes):
  Ping each active panel.
  On failure (3x in a row): mark isOnline=false, notify SUPER_ADMINs.
  On recovery: mark isOnline=true, notify.

pending-receipt-reminder (every 30 minutes):
  Count pending receipts older than 30 minutes.
  If count > 0: notify ADMIN+ users in bot.

broadcast-worker:
  Process jobs from broadcast queue.
  Send 20 messages/second (respect Telegram rate limits).
  Track success/fail counts, update broadcast history record.

subscription-expiry-handler (every hour):
  Find subscriptions where expiresAt < now AND status=ACTIVE.
  Mark as EXPIRED. Do NOT delete from 3x-ui automatically
  (keep config for 7 days in case of renewal).
  After 7 days past expiry: call ThreeXUIClient.deleteClient() → clean up.

═══════════════════════════════════════════════════
CODING RULES (ABSOLUTE)
═══════════════════════════════════════════════════
- TypeScript strict mode: noImplicitAny, strictNullChecks, noUncheckedIndexedAccess
- Every async function wrapped in try/catch with typed errors
- Service layer: controllers/handlers call services, services call repositories
- Zero business logic in route handlers or bot command handlers
- Zero raw SQL with user input — Prisma only
- Never log: passwords, JWT tokens, card numbers, Telegram bot tokens
- All secrets via env — zero hardcoded values anywhere
- Graceful shutdown: listen for SIGTERM, drain BullMQ, close Prisma
- ESLint + Prettier configured with RTL-aware rules
- Tests: Vitest for unit tests on all service methods
- Every new feature needs at minimum one integration test
